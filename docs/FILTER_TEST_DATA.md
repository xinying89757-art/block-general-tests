# 筛选验证的测试数据与 Oracle 设计（40838）

> 本文在“当前实现”之前的内容是历史记录，仅供追溯。

## 实测结论（2026-10-23，预览页）

1. **这个区块只负责筛选 UI，本身不含产品列表**：预览中 `.one-pruduct-list` 等列表元素计数为 0；区块内容就是筛选组 + Reset + Clear Filters + Search + 弹窗表单按钮。
2. **当前实际渲染 2 个筛选组**：
   - `Series`：约 30 个值（Anti Static Packaging Materials、Hydraulic cylinder、Packaging Bags、…、测试分类 等，含产品分类与系列混合值）；
   - `Category`：8 个值（Chemical Bag、Clutch and brake、COMPONENTS / PARTS FOR HYDRAULIC CYLINDERS、Composite Packaging Materials、Custom hydraulic cylinder、Others Hydraulic cylinder、Standard Welded hydraulic cylinder、Tie Rod Hydraulic Cylinder）。
3. **设置里的 7 个自定义筛选字段目前一个都没启用**，所以不出现在前台；启用它们本身就是设置层验证的一部分。
4. **结果呈现位置不在区块内**：点 Search 后应跳到目标产品列表页（设置项「筛选后跳转页 = 默认产品列表页」）或以参数形式带筛选条件，结果集要在目标页核对。跳转/参数的确切形态在能力模块实现时以一次探针定死。
5. 之前探针里「交集匹配 = true」是两个空集的假阳性，不作数；产品名选择器不适用于本区块。

## Oracle 的定义

Oracle = 独立于被测 UI 的预期结果集，来源是内容管理里的产品数据本身：

- 一次性导出/登记产品清单：产品名 + 所属分类/系列 + 每个自定义字段的值，存为 `fixtures/products-oracle.json`（随能力模块维护，数据变更时更新）。
- 任何筛选组合的预期集 = 对该清单按相同规则（交集/并集）做集合运算得到，不从 UI 反推。
- 前台实际集 = 在目标产品列表页采集的产品名集合（处理分页：每页 20 条，采全部分页或先把每页数量设为能覆盖样本的值）。

## 最小判定矩阵（v1）

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 基线 | 不选任何值 | 目标页产品全集（当前分类范围内） |
| 单组单值 | Series 选 1 个值 → Search | 该值对应的产品集 |
| 单组多值 | 同组选 2 个值 → Search | 按组内规则（并集）合并集 |
| 跨组组合 | Series 1 值 + Category 1 值 → Search | 交集（当前设置）下的预期交集 |
| 空结果 | 选一个与任何产品都不匹配的组合 | 空状态/0 条，且不残留上一结果 |
| 清除 | Clear Filters 后重新 Search | 回到基线全集 |
| 已选标签 | 勾选后看已选区 | 标签与所选值一一对应，删单个标签后结果集相应扩大 |

## 数据准备策略

- 优先复用站点现有产品：现有分类/系列值多、产品量足够覆盖单组与跨组场景，v1 不必新造产品。
- 自定义字段场景依赖那批「测试*」字段：它们已有字段定义，但哪些产品带这些字段值尚需在内容管理里核对；若没有产品带值，先补 2–3 个可识别产品（名字带 `AUTOTEST` 前缀）分别挂不同字段值组合，作为长期固定夹具。
- 夹具一旦定版，`fixtures/products-oracle.json` 与能力模块一起进仓库；跑测前先校验夹具产品存在且字段值未被改动（夹具自检），避免数据漂移造成误报。

## AUTOTEST 夹具（当前实现）

精确断言只比较 AUTOTEST 字段和产品，由画像字段值的真值表计算；数量检查只要求数量足够，所有分类模式要求夹具产品存在。上面的历史记录仅供追溯，不是当前期望来源。

字段类型取 `requirements.displayFieldTypes` 与 `fixture.filterFieldTypes` 的并集；后者缺省时使用筛选真值表字段类型。展示需求缺省时才回退 `fixture.supportedTypes`，并发出警告。每种类型的名称与选项由画像提供，准备时按名称核对并补建或修正 AUTOTEST 字段、产品值和分类归属。按站点 host 与区块隔离的身份记录保存在 gitignore 的 `fixtures-state/`，每次运行重新按名称核验。

固定当前分类的检查先选择 AUTOTEST 分类，固定交集照常计算交集；固定交集时并集记为 na。有并集设置的区块仍按满足任一条件的全部夹具产品断言，包括已知并集缺陷。

分类管理入口、分类 ID、产品分类复选框和字段 ID 的具体 DOM 尚未经实站确认；严格定位失败会中止准备，需要先在测试站核验。
