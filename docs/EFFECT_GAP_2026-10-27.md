# 设置项三层验证缺口表（2026-10-27）

盘点基于 main / c28ff26 的代码与文档（58 条明细、56 个检查 ID），全程只读，未登录核实画布实际展示——“后台能看到什么”一列是按设置含义列出的静态核对内容，不是实测画布。

口径（用户 2026-10-27 已确认）：回显＝保存后重开设置面板读值；后台生效＝保存后的编辑器画布静态渲染；预览生效＝预览页面效果。后台只查静态渲染、不查交互：不用点就能看出来的才算后台可查；需要点的交互效果（翻页、选筛选值、点 Clear 恢复、点分类导航、对比流程、跳转）只在预览里查。后台看不到的记“后台看不到”，不硬凑。“有”表示已有实现，不代表本次运行通过；`record` 不算生效验证。临时预览来自 `editor.mjs` 的 `openPreview`，最终前台检查也接收 `preview.frame`，均不能计入后台验证。

## 按钮专项核实结论

`runFrontLayer` 不读取预览按钮的 `href` 或 `target`；`link-href` 只用 `hasAttribute('href')` 检查属性是否存在，不读取地址值，也不读取 `target`，因此真实地址、`javascript:void(0)`、空值均可能通过。按已知背景，40838 设置的是邮箱地址，旧探针在预览中读到的是 `javascript:void(0)`；47748 设置的是不跳转占位内容；当前代码不能提供新的属性值证据。百度方案可行：改为 https://www.baidu.com、保存页面后，若预览按钮呈现真实链接及对应 `target`，读属性即可验证配置映射；若仍是占位链接或由脚本控制打开，则必须点击并观察实际跳转地址及是否新开页面，最后恢复原链接和勾选状态。
